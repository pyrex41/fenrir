## H0 — preserve baseline and publish checked adapter obligations

Before modifying Go sources, inventory and hash original source/executable/binary/
input/tape/dependency/model identities and rerun an original accepted cold replay
and an original generated-failure replay with the unchanged host. Record any
failure honestly; don't rewrite original tapes to make admission succeed.

**Preservation trap:** existing tapes contain absolute workspace source paths,
including host executable hashes. Modifying Go files or overwriting the retained
host invalidates admission. Copying only an old binary is not sufficient; copying
files to another root does not automatically make the old CLI's paths portable.
Retain immutable originals and source bytes, establish a tested baseline replay
strategy, and distinguish historical evidence from new-source captures. If a
portable snapshot/rebased manifest is needed, publish a separate development
contract and test it; never relabel a rewritten tape as exact-original replay.

Publish small executable schema/byte-vector tests for the new host envelopes and
failure taxonomy. Do not amend TC0 semantics or evaluator authority. Explicitly
separate execution (`Completed`, `BudgetExhausted`, crash, watchdog, protocol,
admission, oracle/infrastructure failure), conformance and replay verdicts.
Unknown/incomplete never become admitted completion through aggregation.

Exit: source-preservation inventory, measured baseline results, checked vectors
and one failing distinguishing test per intended admission/lifecycle repair.

## H1 — bounded closed admission and complete replay identities

Audit every artifact/input/header/build/session/tape reader, including ordinary
JSON helper paths (not just the already-strict FGCTL wire decoder):

- Cap bytes before allocation/decoding, nesting and record counts; reject duplicate
  keys, unexpected fields, missing fields, invalid types/ranges and trailing data.
- Define numeric policy per envelope. Existing canonical artifact/transport rules
  stay unchanged; don't impose wire rules on host diagnostics accidentally.
- Independently derive the required model/boot/host/Node/lowering/dependency/source
  inventory. Do not trust an incoming `sources` map to specify which authority
  files are required. Bind model commands, candidate mode, input/initial state,
  images/tender/toolchain inventory and all execution bounds.
- Test omitted model/boot/dependency hashes, swapped executable/image/input/mode,
  truncated or corrupted report, added/removed source files, path/symlink escape,
  output reuse, noncanonical wire bytes and tape header/footer contradictions.
- Reject pre-execution where possible and prove no candidate launch occurred;
  otherwise stop at the first independently observed discrepancy. No fallback.
- Exact original failure replay remains source/binary bound and **Diverged**.
  Changed-source captures/scenario replay are new evidence, never cross-patch
  exactness. Crash/watchdog replay remains Incomplete without a validated captured
  boundary. Diagnostic normalization must be explicit and scope-limited.

Exit: capped closed-reader and inventory negatives pass; actual accepted/rejected
CLI examples retained; admitted current-source complete/budget/divergent cold
replays retain their correct distinct verdicts.
